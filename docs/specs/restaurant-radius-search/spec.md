# restaurant-radius-search: 기준 위치와 반경으로 식당을 찾아 평점순 목록과 지도에 보여 주기

핵심 흐름(`PRODUCT.md`)을 한 번 처음부터 끝까지 통과하는 가장 얇은 결과물이다. 외부 평가 기관 표시, 대표 음식, 가격표는 이번 범위가 아니다.

연결된 소스:
- [PRODUCT.md](../../../PRODUCT.md) — 앱 전체의 전제. 처음 가 본 도시에서 구글 평점과 리뷰 수 같은 근거로 식당을 고르는 사용자, 핵심 흐름, 기능 경계를 정한다. 이 작업은 핵심 흐름의 1·2단계와 4단계를 구현한다.
- [GLOSSARY.md](../../../GLOSSARY.md) — `기준 위치`, `반경`, `평점순 목록`의 정의. 이 문서의 용어는 그 정의를 따른다.
- [ui-composition](../../decisions/ui-composition.md) — 화면 구성은 shadcn 공식 component와 하나의 시각 언어로 만들고, 지도처럼 경험의 핵심인 표면만 custom UI를 허용하는 근거. loading·empty·error 상태와 좁은 화면 규칙도 이 계약을 따른다.

## 사용자에게 보이는 결과

처음 가 본 도시에서 쓰는 사람이 한 화면에서 아래를 할 수 있다.

1. 기준 위치를 정한다. 방법은 세 가지다: "내 위치" 버튼, 장소 이름이나 주소 입력, 지도에서 직접 찍기.
2. 반경을 고른다.
3. 반경 안의 식당이 평점순 목록으로 나타나고, 같은 식당이 목록 순서와 같은 번호의 핀으로 지도에 표시된다.
4. 목록의 각 식당에서 구글 지도를 열어 위치를 확인한다.

목록의 각 항목에는 식당 이름, 구글 평점, 리뷰 수, "구글 지도에서 열기" 링크가 보인다.

## 승인된 범위

- 기준 위치 세 가지 지정 방법: 현재 위치, 장소 이름·주소 입력, 지도에서 찍기
- 반경 선택과, 기준 위치와 반경을 보여 주는 지도 표시
- 평점순 목록(리뷰 100개 이상, 평점 내림차순, 동점이면 리뷰 많은 순)
- 목록과 번호가 일치하는 식당 핀
- 각 식당의 구글 지도 링크
- 로딩·결과 없음·오류·위치 권한 거부 상태

## 수용 기준

실제 구글 API 키로 실행한 앱을 브라우저에서 확인한다.

- AC1. "내 위치"를 누르고 위치 권한을 허용하면 그 좌표가 기준 위치가 되고, 지도에 기준 위치와 반경 원이 보이며 식당 검색이 실행된다.
- AC2. 장소 이름이나 주소를 입력해 제출하면(예: 도시의 역 이름) 그 장소가 기준 위치가 되고, 지도가 그곳으로 이동해 같은 방식으로 검색이 실행된다. 찾을 수 없는 입력이면 찾지 못했다는 안내가 보이고 기존 기준 위치와 목록은 유지된다.
- AC3. 지도의 한 지점을 누르면 그 지점이 기준 위치가 되고 검색이 실행된다.
- AC4. 반경을 바꾸면 지도의 반경 원이 바뀌고 같은 기준 위치로 다시 검색된다.
- AC5. 목록에는 구글 리뷰가 100개 이상인 식당만 있다. 리뷰가 99개 이하인 식당은 나오지 않는다.
- AC6. 목록은 평점 내림차순이고, 평점이 같으면 리뷰 수가 많은 식당이 앞이다.
- AC7. 목록의 각 항목은 이름, 평점, 리뷰 수, "구글 지도에서 열기" 링크를 보여 준다. 링크는 새 탭에서 해당 식당의 구글 지도 페이지를 연다.
- AC8. 목록의 각 식당이 지도에 핀으로 표시되고, 핀 번호는 목록 순서와 같다. 기준 위치는 식당 핀과 구별된다.
- AC9. 조건에 맞는 식당이 없으면 빈 상태 안내가 보이고, 지도에는 기준 위치와 반경 원만 남는다.
- AC10. 위치 권한을 거부하면 거부되었다는 안내와 함께 장소 입력과 지도 찍기로 계속할 수 있다는 것이 보인다.
- AC11. 구글 API 호출이 실패하면 오류 안내가 보이고, 다시 시도할 수 있다. 이전에 보이던 목록이 새 기준 위치의 결과인 것처럼 남아 있지 않다.
- AC12. 검색 중에는 로딩 상태가 보이고, 연속으로 기준 위치나 반경을 바꾸면 마지막 선택의 결과만 화면에 남는다.
- AC13. 좁은 화면(휴대폰 폭)에서도 위치 지정, 반경, 지도, 목록이 모두 보이고 쓸 수 있으며 정보의 사용 순서(입력 → 지도 → 목록)가 유지된다.
- AC14. 구글 API 키는 브라우저로 내려가는 응답이나 코드에서 허용 범위를 넘어 노출되지 않는다. 식당 검색에 쓰는 키는 서버에서만 쓰이고, 브라우저에 보이는 키는 지도 표시용 하나뿐이다.

## 확정된 제약과 근거

- 식당 데이터와 지도는 구글 것을 쓴다. 구글 평점·리뷰 수·지도 링크가 이 서비스가 고르는 근거이기 때문이다. (`PRODUCT.md`, 사용자 확정)
- 기준 위치는 현재 위치, 장소 이름·주소 입력, 지도 찍기를 모두 지원한다. (사용자 확정)
- 평점순 목록은 구글 리뷰 100개 이상인 식당만 넣고, 평점 내림차순, 동점이면 리뷰 많은 순이다. 평점 5.0에 리뷰 3개인 식당이 4.6에 리뷰 3,000개인 식당보다 앞서면 "평점만 보고 고르다 실패한다"는 문제를 되풀이하기 때문이다. 100은 임시값이며 한 곳에서 바꿀 수 있어야 한다. (사용자 확정)
- 검색 결과 식당을 같은 지도에 핀으로 표시한다. 목록의 식당이 기준 위치에서 어느 쪽인지 바로 보이게 하기 위해서다. (사용자 확정)
- 구글 평점 정렬 옵션은 없다. Places API(New)의 주변 검색은 인기순(`POPULARITY`)과 거리순(`DISTANCE`)만 지원하고 한 번에 최대 20곳을 돌려준다. 평점순 정렬은 받아 온 결과를 앱이 다시 정렬한다. (2026-11-19, [Nearby Search 문서](https://developers.google.com/maps/documentation/places/web-service/nearby-search)에서 확인. 텍스트 검색은 최대 60곳이지만 반경은 "편향"으로만 쓸 수 있고 [범위 제한은 사각형만](https://developers.google.com/maps/documentation/places/web-service/text-search) 허용한다.)
- 평점과 리뷰 수는 구글의 상위 요금 등급(Enterprise SKU) 필드라 호출마다 비용이 든다. 필요한 필드만 요청한다. (같은 문서)
- 구현 중 구글 API 요청 형식, 필드 마스크, 제한은 `AGENTS.md`의 안내대로 공식 문서의 현재 내용으로 확인한다.

## 가정 (바꿀 수 있음)

- 데이터는 Places API(New) 주변 검색을 인기순으로 호출해 반경 안 인기 상위 최대 20곳을 받고, 그중 리뷰 100개 이상인 곳을 평점순으로 다시 정렬한다. 인기순은 방문자가 많은 곳을 앞세우므로 "평점과 리뷰 수를 본다"는 의도와 맞는다. 그 결과 목록이 20곳보다 적을 수 있다.
- 식당은 구글의 `restaurant` 유형만 대상으로 한다. 카페·바 등은 이번에 넣지 않는다.
- 반경 선택지는 500m, 1km, 2km, 3km이고 기본값은 1km이다.
- 기준 위치가 정해지기 전에는 검색하지 않고, 지도와 위치 지정 안내만 보인다. 기준 위치를 정하거나 반경을 바꾸면 자동으로 검색한다.
- 화면 문구와 구글 데이터의 언어는 한국어다. 템플릿의 `lang="en"`은 한국어로 맞춘다.
- 장소 이름·주소를 좌표로 바꾸는 것도 Places API(New)로 하므로 사용 설정할 API는 추가로 늘지 않는다.
- 현재 위치는 브라우저 위치 권한으로 얻는다. 권한은 HTTPS 또는 `localhost`에서만 동작한다.
- 화면 레이아웃은 `ui-composition`을 따른 한 화면 구성(입력 영역, 지도, 목록)이다. 세부 배치는 구현이 정하고 AC13으로 확인한다.

## 범위 밖과 이유

- 미쉐린 등 외부 평가 기관 평가 표시 — 핵심 흐름 3단계의 별도 작업 단위. 이번 목록은 구글 평점·리뷰 수만 쓴다.
- 리뷰에서 가장 많이 언급된 음식 추천, 리뷰 속 신뢰 표현 확인 — 별도 작업 단위.
- 음식 가격별 표 — 별도 작업 단위.
- 로그인, 즐겨찾기, 검색 기록 저장 — 요청되지 않았고 핵심 흐름에 필요하지 않다.
- 구글이 아닌 데이터 출처, 길찾기·예약 — 요청되지 않았다.
- 보안 하드닝·엣지케이스·성능 방어 — AGENTS.md 검증·리뷰 예산. AC14의 키 노출 방지는 이 범위 안의 최소 요건이다.

## 미뤄 둔 결정

- 평점과 외부 평가 기관 평가를 합쳐 순서를 만드는 방식, 리뷰 속 신뢰 표현이 순서에 영향을 주는지 — `PRODUCT.md`가 아직 정하지 않은 열린 질문이다. 이번에는 구글 평점 하나(리뷰 100개 이상)로만 정렬한다. 이 결정을 다시 여는 조건: 외부 평가 기관 평가를 목록에 넣는 작업 단위를 shape할 때. 연결된 이슈 없음.
- 반경 안 모든 식당을 평점순으로 보여 줄지(구글의 20곳 제한을 넘는 방법) — 이번에는 인기 상위 20곳 안에서만 정렬한다. 이 결정을 다시 여는 조건: 쓰는 사람이 목록에서 알려진 식당이 빠졌다고 확인하거나, 외부 평가 기관 평가 작업 단위를 shape할 때 데이터 범위를 함께 확인할 때. 연결된 이슈 없음.

## 남은 위험

- 인기 상위 20곳만 보므로, 인기는 낮지만 평점이 높고 리뷰가 100개 이상인 식당이 빠질 수 있다. 리뷰 100개 이상 필터 후 목록이 짧게 나올 수 있다.
- 평점·리뷰 수는 호출 비용이 드는 필드이고 기준 위치나 반경을 바꿀 때마다 검색이 실행된다. 학습용 규모에서는 문제가 아니지만, 사용량이 늘면 비용 확인이 필요하다.
- 브라우저에 보이는 지도 키는 노출을 막을 수 없으므로 허용 도메인 제한이 없으면 남이 쓸 수 있다.
- 구글 API의 필드·제한·요금 등급이 바뀌면 이 문서의 근거가 달라질 수 있다.

## Setup before implementation

- 결제가 켜진 구글 클라우드 프로젝트와 그 프로젝트에서 Places API(New)와 Maps JavaScript API 사용 설정 — 식당 검색과 지도 표시를 위해 필요 — 완료 조건: 앱 밖에서 서버용 키로 Places API(New) 주변 검색(`places:searchNearby`) 요청을 보내면 평점(`rating`)과 리뷰 수(`userRatingCount`)가 있는 결과가 오고, 콘솔의 API 사용 설정 목록에 두 API가 보인다.
- 서버 전용 API 키 1개 — 식당 검색과 장소 이름·주소를 좌표로 바꾸는 호출을 서버에서 하기 위해 필요 — 완료 조건: 위 앱 밖 호출이 이 키로 성공한다.
- 브라우저 지도용 API 키 1개와 허용 도메인(`localhost` 등) 제한 — 지도 표시와 지도 찍기를 위해 필요 — 완료 조건: 허용 도메인에서는 Maps JavaScript API 로드가 성공하고 다른 도메인 요청은 콘솔 설정상 거부된다.
